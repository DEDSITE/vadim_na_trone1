## Уроки этапа 2
- В облаке и в шелле-VM мака npm/pip/github закрыты, но у **настоящего** мака Димы интернет есть → всё, что требует установки (Remotion, шрифты с Google Fonts), делаем на маке через `.command`-скрипт, запуская его из Finder.
- Терминал через управление экраном — только клики (печатать нельзя), Финдер — полный доступ. Если Дима в полноэкранном приложении — Финдер «на другом рабочем столе» и не кликается: попросить переключиться на обычный рабочий стол.
- Переносить файлы «текстом» (base64 через вывод браузера) ненадёжно — контрольная сумма не сошлась. Не делать.
- Перезапись файлов в папке мака: tar не может перезаписать (нет unlink без разрешения) — распаковывать во временную папку и `cat src > dst`. Для git commit нужно разрешение на удаление (lock-файлы) — `device_request_delete_permission`.
- Компиляция в облаке: `build/cpdump/*.jar` стейджить в облако тремя пачками ≤50 файлов, исходники — `tar` без `menu_video` → `/home/claude/w/build.sh`. Сервер в облаке — KnotServer, мод — объединённая папка классов+main/resources в `-Dfabric.addMods`, RCON — `/home/claude/rcon.py`. Без игроков `/vadim news` ничего не делает — полностью катсцену проверяет только Дима.

## Как проверять (до запуска у Димы)
- Компиляция в облаке: classpath из `build/cpdump` → javac (`/home/claude/w/build.sh`).
- Сервер в облаке: KnotServer с `-Dfabric.development=true -Dfabric.gameMappingNamespace=named -Dfabric.runtimeMappingNamespace=named -Dfabric.addMods=<классы+ресурсы>`, RCON для команд.
- Шейдеры: компиляция через Mesa (EGL surfaceless).
- Блоки Macaw's сверяются с blockstate-файлами jar из ~/.gradle/caches/modules-2/files-2.1/maven.modrinth.
- Картинки GUI: макет-превью собирается в PIL из тех же PNG и координат, что в коде.
- Клиент в облаке не запустить (нет нативных LWJGL под Linux) — картинку проверяет Дима.

## Уроки этапа 1
- Порт Стрипухоеда на 1.21.11 НИКОГДА не запускался — его клиентский код считать непроверенным.
- После КАЖДОЙ выкладки на мак сверять md5 всех файлов src на маке и в облаке (0 расхождений), только потом звать Диму. Большие архивы (>~30 МБ) device_commit_files не берёт — тяжёлые файлы (кадры видео) готовить прямо на маке ffmpeg'ом и копировать там, а в облако забирать через device_stage_files для сверки.

- Если в видео есть хоть малейшее движение камеры, нельзя «оживлять» только часть кадра — получается кривое наложение. Видео — целиком.
- Неотправленные коммиты с тяжёлыми ассетами, которые потом заменились, — схлопывать (git reset --soft), чтобы старые кадры не уехали на GitHub.
